# 規格整理 v 1.2.0

## 技術規格文件

**能力與工具綁定模組** · 2026-11-26 · RK-NEXT Graph 2.3

### 1. 目標、背景與範圍

設計者能查藍圖的綁定、候選及缺口。安裝者可從任一入口接續同一補強工作。維運者可對照已裝版本的鎖定與實際環境，遇到失效時沿原 Run 補強。交付包含六種可實際派送、驗證及回復的綁定，與三條缺件處理路徑。候選須通過 IR、wheel RECORD、隔離載入及安裝前重驗。

本規格延伸[通用工具鏈補全](../toolchain-completion/technical.md)。現有程式已有清冊、候選篩選、隔離準備、資格收據、環境鎖定與重綁。藍圖補強目前在工作鎖內依序準備、驗證及排入試做。跨宿主操作由宿主接續，Studio 現行文字串流會拒絕 `tool_calls`。 [補強入口](../../../flow_base/src/flow_base/blueprints/completion.py) · [Studio 模型介面](../../../workflow_studio/src/workflow_studio/llm/provider.py)

**設計前提。** 沿用 Python、uv、SQLite、FileLock、CLI 與 MCP stdio。Studio 可使用自己的設計環境，每個工作區指定一套執行環境。採用現有 Studio 對話與 CLI，Run、Artifact、公開入口及舊藍圖納入相容驗收。

### 3. 初始安裝與目標執行環境

1. **一個工作區、一個執行環境。** 整合安裝用根層 `.venv`，開發樹可明確選 `flow_base/.venv`。整合版 Studio 無論從哪一端啟動，都取得目標工作區與同一 Runtime。獨立 Studio 管理自己的工作區時，才用隨附 Runtime。實際執行後回報 `sys.executable`、`sys.prefix`、Python／底座版本、平台與架構。以 `sys.prefix` 驗證 venv 身分，避免 POSIX 的 Python 符號連結被解析成系統 Python。
2. **先定位失敗，再判定缺件。** 啟動依序核對工作區、Runtime、套件鎖、暫存可寫性、版本探測和工具清冊。依證據區分環境錯配 `RUNTIME_MISMATCH`、確實缺件 `DEPENDENCY_NOT_INSTALLED`、暫存不可用 `STAGING_PATH_UNUSABLE`、準備 I/O 失敗 `PREPARATION_IO_FAILED`、宿主不可用 `HOST_UNAVAILABLE`。沿用舊錯誤的相容映射，回傳原 OS error 和已遮罩的 stderr 摘要。清冊未取得顯示待觀測。
3. **Windows 路徑自動恢復。** 驗證工作區專用 staging 和 uv cache 的寫入、替換及可用路徑深度。出現深層路徑寫入錯誤時，以同一操作 ID 改用已核對的短、隔離 staging 重試一次。驗證位置、所有權、連結和空間，成功後原子採用。兩處都不可用時保存路徑與具體處理方式，原環境仍可回復。短路徑修正涵蓋冷啟動、依賴準備與資格試做。
4. **兩種故障分開驗收。** 已觀測到 Studio 開發環境為 0 個可攜 Adapter、底座開發環境為 2 個、正式 Runtime 為 7 個課程 Adapter。另一案例是同一 Python 因 uv 深層暫存快取寫入失敗而出現缺件，換短路徑後安裝與重綁通過。以不同測例覆蓋。 [Studio bridge](../../../flow_base/src/flow_base/studio.py) · [獨立啟動器](../../../workflow_studio/scripts/studio_bootstrap.py) · [uv 準備](../../../flow_base/src/flow_base/graph/preparation.py)

### 4. 併行與一致性

綁定路徑為確認環境 → 查已鎖定與即時狀態 → 建立缺口與候選 → 篩選及核准 → 準備 → 資格驗證 → 鎖定 → 隔離試做 → 安裝前重驗 → 採用或重綁續做。每一階段以具名工作寫入依賴圖。

| 可併行 | 有依賴或需互斥 |
| --- | --- |
| 已連線清冊、Skill ZIP、受信配方和本機元件的讀取 | 探測指定 Python 內的套件前先確認環境。觀測指紋變更後重算受影響候選。 |
| 無副作用探測、不同隔離目錄的準備、獨立案例 | 相同依賴指紋只準備一次。共享環境寫入、同一寫入目的地和獨占裝置需取鎖。 |
| 不同需求的備選方案及已授權的獨立派送 | 核准、領取、回執與採用有固定順序，單一操作只允許一個派送者。 |
| 待授權期間的其他獨立分支 | 暫停依賴待確認輸出、超過額度或衝突於高風險資源的工作。 |

以依賴圖的就緒單位排程，完成順序與政策排名獨立。初始預設每工作四個本機探測槽、兩個宿主槽、每台 MCP server 及每個 GPU 各一槽。可依工作區和能力配置調整；環境超載降至串行。未知副作用按獨占處理。測試量測區分冷、熱和競爭狀態。

耗時推論若偵測到可用 GPU，先向使用者提出 GPU 選項，待確認後把選定裝置寫入工作步驟。資格驗證核對實際裝置。已確認 GPU 執行遇到後端失效時保留續作狀態，交由使用者確認裝置變更。

在短 SQLite 交易中領取與保存結果，鎖外執行子程序、模型與網路探測。租約帶世代；過期結果、舊修訂與不同 `scope_hash` 無法覆蓋有效結果。無可執行工作時保存等候原因，CLI／MCP 下一次推進或顯式 Worker 接續。已領取又缺回執時按操作 ID 查核，確認未執行且可重試才再次送出。以有限重試及觀測指紋避免無進展循環。取消停止新領取，正在執行的工作依其回執規則結束。

### 5. 六種綁定的完成定義

| 方式 | 探測、接線與實際執行 | 最小可驗收案例 |
| --- | --- | --- |
| **Code-as-a-tool** | 確認可信 wheel、entry point、版本及 RECORD 指紋，依具名輸入、參數、素材引用呼叫隔離 Python Runner。字幕優先重用 faster-whisper，依藍圖配置模型和資料映射，產出片段與時間證據。 | 用字幕藍圖驗證實際推論、模型版本、輸出格式與時間證據；用替身覆蓋失敗。 |
| **Skill 綁定** | 保存完整 ZIP 與版本，安全讀指定腳本及依賴。為腳本建立具名 Adapter、輸出及錯誤映射並隔離試做；只有文字規則的 Skill 轉為宿主模型指令並取得實測。 | 以含腳本及只有規則的 Skill 各跑一條路徑，覆蓋腳本缺失與指紋漂移。 |
| **MCP Tool** | 由受信連線觀測 `tools/list`，固定來源 ID、工具名、版本與契約。領取後由具連線的宿主執行 `tools/call`，核對結構結果及 `isError`，保存可信回執。缺輸出契約時先建立並驗證映射。 | 真實測試 server 完成觀測和呼叫，斷線後可查原回執，重複領取沒有第二次派送。 |
| **ToolCalling Tool** | 模型提出具名函式呼叫，宿主辨識完成的參數串流、核對已鎖定工具與權限、實際派送，依呼叫 ID 把具名結果送回模型，驗證最後成果。 | 替身覆蓋分段參數、相依及獨立呼叫、重名、未知工具、截斷、額度、核准。另用一個已配置且確認支援的本機模型實跑往返。 |
| **CLI Tool** | 具名宣告絕對執行檔、來源、版本探測、合法參數模板、執行目錄及輸出解析。以參數陣列啟動、限制環境與路徑、設定逾時及輸出長度，驗證 JSON、格式化文字或具名檔案。 | 以 ffprobe 讀取測試媒體，測中文、空格、特殊字元、診斷與逾時。 |
| **宿主 LLM 執行** | 讓任意具有契約的文字工作具名指定模型角色、資料範圍、輸出、預算和觀測來源。沿用宿主待辦、模型 Streaming 與可信結果回填。 | 真實宿主完成文字輸入、增量輸出、結構結果及用量核對；中斷保留待查工作。 |

ToolCalling 可調用已驗證的 Python、CLI 或 MCP Adapter，沿用各自權限。模型供應器須實測支援。工具模式着手於完整解析的呼叫，保留原先 Studio 的純文字模式。每輪暫定最多 4 個工具提議、最多 3 輪，受工作總預算及個別工具權限約束。每個發出模型或工具請求的邊界先扣抵，模型收到工具結果後的下一次請求也計入。獨立且獲准的工具可併行，回填按原呼叫 ID 和順序。截斷的參數、超額、未列入核准範圍的工具及重複 ID 附不同參數，均不派送。字幕 0／4／5／9 段用量、超額預攔截與未知回執防重送為必要回歸。

### 6. 三條缺件處理路徑

| 路徑 | 自動接續 | 暫停與恢復 |
| --- | --- | --- |
| **推薦等效方案** | 先硬篩資料語意、輸入輸出、版本、平台、離線、授權、目的地、成本、副作用。優先有效既有綁定、已驗證本機、可安全準備、需授權；保留淘汰理由。既有等效政策適用時直接重驗。 | 有實質資料、費用或權限差異時，合併顯示可勾選的方案，候選及確認綁定當時修訂與範圍。重驗不符回到下一個可行候選。 |
| **查第一手安裝方式並準備** | 先查本機和受信配方。宿主用公開工具名與能力需求查原廠，保存來源、版本、相依、校驗、平台、授權與回復方式。已授權的下載及鎖定依賴進隔離 staging，校驗後再試做。 | 未知來源、暫無核准或需系統層變更時保留可比較選項。取得材料或授權後沿原工作續做，保留可驗證的取得證據。 |
| **自行實作** | 依契約重用 Skill、既有程式或建立最小 Adapter；建立具名映射與可重跑正反案例。具受控執行器時完成原始碼封存、隔離建置、註冊候選、試做與資格驗證。 | 外來、生成程式依實際可施加的檔案、程序、網路、資源限制執行。缺執行器、素材或授權時，保存程式與具體待補事項。 |

同一缺口的三條路可併行唯讀評估，採用動作鎖定修訂，一個範圍只採用一套方案。受限 WebAssembly 用於相符的純運算，其他適用路徑須具相應執行限制。搜尋結果、工具文字與 Skill 文件當作資料處理。已有成果在環境及用量範圍一致時直接沿用。執行中重綁保存 `session_id`、`root_run_id`、`active_run_id` 與原 `rebind_work_id`。

### 7. 資料、持久化及公開操作

| 物件 | 主欄位與保存規則 |
| --- | --- |
| 執行環境與觀測 | `workspace_id`、`runtime_id`、Python 路徑、底座版本、平台、版本觀測代次及指紋。狀態為可用、待觀測、錯配和探測失敗。 |
| 需求、缺口、候選 | 藍圖／Workflow／Run 來源、`node_id`、`gap_id`、`scope_hash`、工具、輸入輸出、權限、決策、候選與淘汰理由。結果與觀測代次對齊。 |
| 工作與子工作 | `work_id`、`revision`、`operation_id`、依賴、資源鍵、租約世代、重試、狀態與回執。SQLite 以操作鍵去重。 |
| 資格、授權與採用 | 工具及模型版本、案例、用量、結果、資料及授權範圍指紋。保存真實答覆、不可變資格收據與版本化鎖。 |

子工作由 `pending` → `ready` → `claimed` → `succeeded` 或 `failed`。資料、授權及未知送出結果分別進入 `waiting_input`、`waiting_approval`、`reconcile_required`。重新探測或補件後推進同一工作；封存保留修訂。維持現行 `blueprint-completion`／`blueprint_completion` 的 `find`、`status`、`start`、`advance`、`recheck`、`submit` 與 `history`。更新須含 `request_id`、`expected_revision` 和適用的 `scope_hash`。手動和自動排程介面使用同一寫入規則。刪除沿用無引用暫存的預覽與核准清理。

先備份 SQLite、資格和鎖並驗證可還原，再擴充欄位或表。檔案採用與 DB 提交之間保留待完成狀態供重啟核對。測試工作區只收到必要觀測和測資，正式收據與授權作用域獨立。UI 重連重讀底座狀態，模型 Streaming 與工作事件各有序號和狀態。

### 8. 宿主任務、資訊與揭露規則

| 角色與任務 | 預設可見 | 展開細節 |
| --- | --- | --- |
| 設計者查藍圖 | 已鎖定、待驗證、缺口、可繼續工作 | 候選差異、來源、資料用途與欄位預覽 |
| 安裝者處理補件 | 可自動處理的步驟和需要決定的事項 | 執行路徑、失敗階段、遮罩後錯誤、版本與來源 |
| 維運者採用重綁 | 原 Run、影響節點、可沿用成果和待查回執 | 權限變更、用量、前版回復來源、已做及待做案例 |

使用既有對話、CLI 及可選勾選呈現。先顯示有待決定和下一個可執行步驟，其餘可展開。中性色呈現進度、琥珀提示待決定、深紅提示明確錯誤，配文字支援黑白終端。只展示決策有關資訊，附件沿用本機預覽與影音等比呈現，有限制時給檔案與範圍說明。日誌遮罩祕密與私人資料，原素材不作診斷預設。

主要任務是讓本次綁定工作達到可驗證結果。次要任務是比較候選與補件，低頻任務是查看歷史與來源，罕見任務是還原、取消或查未知回執。

| 進入狀態 | 當下呈現 | 次要資訊及可用操作 | 離開條件 |
| --- | --- | --- | --- |
| 探測或準備中 | 首屏列可繼續工作與真實計數 | 事件細節可展開；開始／接續對應 `advance` | 必要項目通過或出現待處理事項 |
| 等補件或授權 | 顯示來源、實際資料範圍、成本、影響分支與選項 | 排除未涉及的候選；補件／確認對應 `submit` | 同一修訂取得補件、確認或拒絕 |
| 回執待查 | 顯示送出狀態、影響節點與回執識別 | 展開已遮罩的事件；查原回執對應 `reconcile` | 取得可核對的結果或已確認未執行 |
| 驗證錯誤 | 顯示原因、階段、可執行恢復方式 | 錯誤詳情按需展開；檢查對應 `recheck` | 失敗條件改變並重驗 |
| 綁定完成 | 顯示鎖定版本、驗證和待正式 Run 的案例 | 歷史、指紋與還原來源按需展開 | 出現版本漂移或新的修訂 |

開啟、選擇、批准、領取、放行、取消和重連由既有公開操作觸發。底座寫入操作 ID、來源、修訂和實際結果，每次重連讀回上次保存的狀態與進度。螢幕首層保留有用的計數、資料範圍和下一步；工具清冊全文、堆疊和內部排程細節留在診斷與歷史。

### 9. 驗收矩陣
