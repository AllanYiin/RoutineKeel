# 同工作區跨專案重用 Handler

目前流程完成獨立試做後，選取自訂資料處理步驟，再按「將已試做的自訂處理保存為工具」。
填寫工具識別碼、版本、名稱、保存者與理由；Studio 重新核對目前 Revision、套件 hash、
通過報告及案例版本，再保存固定的程式、型別、預設參數與合成測試。
新工具先列為 untrusted，需到工具管理核對用途、參數與驗收依據後明確核准。

保存不複製來源表或 Golden Case 資料列，但程式與合成測試本身可能含私人內容，保存前仍須核對。
這是同一工作區內的共享工具庫，不是對外發布。原專案封存後，新專案仍可使用固定快照；
工具停用或撤回核准則會阻擋後續編譯／發布，並不自動卸載已安裝流程。

核准後可在另一個專案的手動起案、步驟新增或模型分析中選用。
模型只取得用途與參數型別，使用 `parameters={"arguments":{...}}` 提供覆寫值；
未提供的值在本機套用預設值。固定程式、合成測試及預設參數不額外加入模型請求。
模型修復傳送的 registered-handler 節點也只含參數覆寫；重測結果與差異仍屬修復資料同意的範圍。
新專案必須提供自己的成功案例並重新驗證，不能直接沿用原專案的「已通過」狀態。

每個工具版本的模板不可變。工具契約中的 `studio-handler-sha256:` 綁定完整參數規格的內容指紋，
因此核准的 contract hash 同時綁住程式、型別、測試與預設值。
儲存流程時會在本機展開完整快照進 IR；編譯與獨立驗證會再次比對固定模板。
程式、測試、用途或參數型別不能透過節點覆寫；只允許已宣告且型別相符的參數值。
生成的流程包包含完整程式與受控執行器，Runtime 不必讀取原專案或 Studio 工具庫。

在工具管理另存新描述時，固定模板會一同複製，仍需重新核准；舊版本保持不變。
若程式需變更，先在流程中以新生成處理完成獨立試做，再保存新的工具版本。
只有描述 JSON 而缺少固定模板時，工具不能被視為可用；目前尚未提供跨工作區模板匯入／匯出包。

模板上限為 2 MiB，重用展開後的 IR 上限為 8 MiB；超限會拒絕整筆寫入，請精簡合成測試或預設資料。
這些限制不會截斷內容，也不會破壞原專案、案例或既有模板。
目前有實際跨專案重播、原專案封存後重用、版本與型別保護及模型請求隱私測試，
模型回應仍為 fixture；新按鈕與表單未實機走查，不能視為完整產品驗收。
