# 業務規則與人工確認

「業務規則／證據確認」從目前有效流程顯示規則說明、來源版本、位置及引用步驟，
可以新增／修改說明、調整引用、移除未引用規則，以及確認或撤回已保存的規則。
文字與支援的圖片以保存的來源 bytes 預覽，圖片依比例縮放。新視窗尚未做實機視覺驗收。

修改規則說明不會自動改寫節點程式、分支條件或參數；實際算法修改仍使用流程編輯與模型修復，
之後重新執行固定案例。人工確認表示具名使用者對來源與規則的判斷，不是算法已涵蓋所有輸入的保證，
也不授予工具、網路或發布權限。

`StudioService.evidence(policy)` 提供 edit／decide／remove；每次操作使用專案 expected_version，
建立新的不可變 Revision，並與決策／事件紀錄同交易提交。失敗整筆回復。
引用中的規則不能直接移除；調整引用不得讓任何節點失去全部證據。
UI 必須先保存內容，才對已保存內容輸入確認者與理由；未保存的表單不能被確認。

SQLite v010 保存 append-only 決策。每份確認綁定專案、evidence_id、來源 ID／版本／hash、
檔案 hash、位置及規則文字；內容指紋不是數位簽章，單使用者本機信任邊界仍適用。
`human_confirmed` 只能引用同專案、同內容、未被後續撤回的確認 ID。
任何來源版本、位置、規則文字或識別碼改變都不能沿用舊確認。
模型的高信心、來源中的「已批准」指令、其他專案的紀錄或把人工確認冒充 `verified` 均不被接受。
`verified` 可引用已保存且能重新查核的固定 Runtime 試做案例，入口及範圍見
[機器驗證證據](machine-evidence.md)；不可把人工確認偽裝為機器驗證。

撤回保存新紀錄，不覆寫或刪除原決策。相同 basis 的先前確認一起失效；之後重新確認會建立新 ID。
順序以不可變的持久化 sequence 判定，不依系統時鐘或可重編號的隱含 rowid，VACUUM 後判斷不變。
保存、編輯、續編、編譯、獨立靜態驗證與模型修復均核對這份依據。
核准寫入及正式 manifest 切換前也會在交易內重檢，避免準備期間撤回後仍發布。

撤回不刪掉歷史報告，也不自動卸載已安裝版本；它會阻擋依賴舊確認的新驗證／核准／發布操作。
已安裝包如需停用，仍由使用者透過發布管理明確操作。
這個紀錄系統不取代整體業務驗收、第三方身份驗證或最終發布核准。
