# 本機工作台（開發版）

Windows 在原始碼工作區雙擊 `routinekeel/workflow_studio/open_studio.bat`。
其他平台或維護者可在根目錄執行：

```text
uv run --project routinekeel/workflow_studio --group dev python -m workflow_studio --workspace . ui
```

先填專案名稱、工作目標及成功條件，按「建立專案」。選取文字、Mermaid 或成功案例資料夾，
在右側預覽實際內容。來源替換與移除會保留版本及原始檔，不會直接刪除使用者資料。

已有原始輸入與正確成果時，可使用「從成功案例找流程」。選取候選後會保存流程及固定案例。
需要模型分析時，先設定端點、模型、已查核的費率與預算；送出前會確認來源範圍。
金鑰不保存至專案，且依目的端區分本次工作台的記憶體憑證。

點選流程步驟可修改輸出名稱及支援的選項；有其他步驟或成果依賴的節點不能直接刪除。
在「試做與發布」指定輸入及正確成果，可為多個交付物分別配置案例。
試做會在獨立工作區執行底座，再與固定案例比較，失敗時顯示原因與有界文字差異。
模型試做另顯示模型目的端、案例與保守預算上限，確認前不會傳送資料或憑證。

試做通過後，填入核准者並確認成果，才能發布到選定的本機工作區。
核准綁定套件指紋及驗收版本；修改來源、目標、案例或流程後需重新驗證。
發布採用版本快照與原子 manifest 切換，保留既有 outputs 與舊 wheel；可從發布歷史回復舊版。
關閉或切換前會提示尚未儲存的目標，進行中操作不會被假稱已停止。

此工作台是新增的 Studio 介面，沿用 Tk 模式並使用 flow_base 的 WorkflowService。
它不取代底座原本的本機工作台。開發版尚未完成完整規格、真實模型、三平台及真人案例驗收；
影片推導維持 P2 實驗功能、預設停用。可用性與已知範圍見 test-report.md 及 ui-review.md。
