# 本機工作台（開發版）

Windows 在原始碼工作區雙擊 `routinekeel/workflow_studio/open_studio.bat`。
其他平台或維護者可在根目錄執行：

```text
uv run --project routinekeel/workflow_studio --group dev python -m workflow_studio --workspace . ui
```

先填專案名稱、工作目標及成功條件，按「建立專案」。選取文字、Mermaid 或成功案例資料夾，
在右側預覽實際內容。來源替換與移除會保留版本及原始檔，不會直接刪除使用者資料。

已有原始輸入與正確成果時，可使用「從成功案例找流程」。選取候選後會保存流程及固定案例。
需要模型分析時，先設定端點、模型、已查核的費率與預算；送出前會確認來源範圍。
金鑰不保存至專案，且依目的端區分本次工作台的記憶體憑證。

不需模型時，也可按「手動建立第一個流程」，選擇來源、第一個基本動作、實際輸入格式與輸出檔名。
這會建立待試做版本，不會執行流程或把業務規則標成已確認。已有流程時，請使用新增步驟或歷史續編。

點選流程步驟可修改輸出名稱及支援的選項；有其他步驟或成果依賴的節點不能直接刪除。
「新增步驟／連線／交付物」可新增已允許的基本動作，或重用目前流程的自訂步驟，
並調整輸入來源、前置步驟、輸出檔名及最終交付物。整組修改保留在表單中，按儲存後才提交。
移除仍被引用的步驟時，可先在同一份表單中重新連線並調整交付物；檢查不過不會留下半改好的版本。
輸入格式是契約宣告，不會自動轉檔。每次儲存都重新檢查循環、型別、引用及編譯支援，並須重新試做。
手動第一步提供複製、文字整理、JSON 整理及指紋報告；連線視窗也能新增確定性分支，
啟用執行期模型並配置預算後可新增模型步驟。已有的生成處理與其他步驟可重用。
新演算法仍由模型產生。這些新增編輯視窗的實機走查尚待完成。

「調整步驟」以分頁表單修改輸出檔名、完成時間、快取、執行前檢查及完成條件。
文字動作可調整空白與換行，自訂處理保留其參數型別；分支可選判斷方式及兩路動作，兩路必須具有共同輸出契約。
模型步驟可調整處理要求、輸出欄位、端點、模型、呼叫／Tokens／時間上限、費率與預算。
各模型步驟預算總和不能超過專案工作流設定；修改後舊試做授權失效，送出資料前仍須重新確認。
模型與外部副作用不使用快取，也不自動重送。這些設定不會直接執行任何外部操作。
「版本與差異」可查看所有保存紀錄（含已捨棄草稿），比較選取版與目前版的內容。
「從這版續編」另建新的版本並記錄來源，不會切換已發布的流程；目標不同時需明確勾選同時還原。
捨棄只隱藏未發布草稿，保留歷史內容；已核准或曾發布的版本受到保護。
尚有未儲存目標或專案已封存時，版本視窗只供查看。
在「試做與發布」指定輸入及正確成果，可為多個交付物分別配置案例。
「編輯案例／歷史／封存」可查看歷史輸入與正確成果的文字預覽，修改名稱、交付物、比較規則，
或替換檔案後另存新版；也可從封存前的歷史內容建立新版並重新使用。
這些修改都需要重新試做與核准，舊報告仍保留原來的案例版本。
編輯期間有人修改專案時，會拒絕過期儲存；無效資料不會留下部分匯入來源。
案例歷史視窗可分頁查看當時保存的輸入與正確成果，支援文字及圖片等比預覽；新視窗尚未做實機視覺驗收。
試做會在獨立工作區執行底座，再與固定案例比較，失敗時顯示原因與有界文字差異。
模型試做另顯示模型目的端、案例與保守預算上限，確認前不會傳送資料或憑證。

已有模型設定且試做失敗時，可按「根據試做差異修復（最多兩輪）」。
這次會另行確認傳送的流程程式、案例輸入、正確成果、差異與預算，並逐段顯示修復說明。
每輪有效修正都會重新試做；案例與比較規則不會被模型改寫。若仍失敗或規則不明，
請查看失敗報告／待確認問題後補充來源。修復成功也不會自動發布。
目前支援範圍與驗證限制見 [模型修復](model-repair.md)。

試做通過後，填入核准者並確認成果，才能發布到選定的本機工作區。
核准綁定套件指紋及驗收版本；修改來源、目標、案例或流程後需重新驗證。
「業務規則／證據確認」可查看來源、修改規則說明與引用步驟，並記錄具名確認或撤回理由。
請先保存規則，再對保存內容作出決策；內容改變後不能沿用舊確認。
撤回會使相同內容的先前確認失效，但不會自動卸載已安裝流程；詳細範圍見 [規則確認](evidence-decisions.md)。
發布採用版本快照與原子 manifest 切換，保留既有 outputs 與舊 wheel；可從發布歷史回復舊版。
關閉或切換前會提示尚未儲存的目標，進行中操作不會被假稱已停止。

此工作台是新增的 Studio 介面，沿用 Tk 模式並使用 flow_base 的 WorkflowService。
它不取代底座原本的本機工作台。開發版尚未完成完整規格、真實模型、三平台及真人案例驗收；
影片推導維持 P2 實驗功能、預設停用。可用性與已知範圍見 test-report.md 及 ui-review.md。

技術管理者可從上方「工具管理」查看契約、建立新版本、匯入描述並核准／撤回／停用工具。
這是工作區共用設定，會影響所有專案的後續編譯及發布，不會自動卸載已安裝流程。
註冊、核准及可編譯是三種不同狀態，詳見 [工具治理](tool-registry.md)。

已通過試做的自訂處理可保存為同工作區的可重用工具，核准後供其他專案選用。
其他專案只需調整已宣告參數，仍以自己的案例試做；詳見 [Handler 工具庫](handler-library.md)。

「建置歷史／審核／報告」可查看程式、歷次報告與保存事件，並送審、退回、撤回核准或封存未發布建置。
新增或更新案例後必須完整重測，退回也不能只靠重新建置相同流程就繞過。
發布歷史可停用目前版本並記錄理由；詳見 [建置審核](build-reviews.md)。
