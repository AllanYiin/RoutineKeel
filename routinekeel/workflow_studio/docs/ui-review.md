# Windows 工作台實際檢查

使用者回報畫面模糊後，以原生視窗截圖確認：舊版內文遭 Windows bitmap 縮放、
CJK 字體回退、左側底部控制項裁切、預覽區過度佔寬，及未建立專案時的無效操作按鈕。
這些問題不是由既有 widget 測試通過就能排除，因此增加實際畫面與操作驗證。

本機螢幕回報 144 DPI／150%。修正只設定 Studio 程序的 DPI awareness，
不修改 Windows 全域顯示設定；在建立 Tk 視窗前啟用 per-monitor-v2，
再按本視窗 DPI 設定字體、初始大小與控制項間距。
實際可用 CJK 字體選用 Microsoft JhengHei UI，其他平台依可用字體回退。

已調整：

- 白色工作面板、固定欄位比例與可伸縮來源清單；底部操作保持可見。
- 目標與成功條件支援多行輸入；流程圖可按依賴分層並橫／直捲動。
- 建立、來源、候選、節點、試做與發布按鈕依前置狀態啟用。
- 顯示未儲存狀態，切換專案／工作區或關閉前保護輸入。
- 新增專案與儲存目前專案分開，切換工作區時清除舊來源預覽。
- 模型設定顯示已保存的非機密欄位，表單錯誤不改寫既有設定。
- 設定／案例等對話框限制在目前工作區上下文，避免操作錯專案。
- 試做準備也移至背景工作，視窗可持續更新狀態；不在關閉後繼續啟動下一步。

原生 CUA 實際選取流程步驟、切換「試做與發布」並執行本機固定案例，畫面顯示試做通過。
使用者回覆「UI 好多了」。這是本次 Windows 畫面證據，並非 macOS／Linux 或 20 件非技術案例驗收。

回歸：`test_ui_readability.py` 驗證字體、多行欄位、按鈕狀態、未儲存保護、最小視窗邊界及設定原子性。
`test_real_tk_buttons_complete_folder_to_verification` 覆蓋建立→匯入→採用→試做→發布與等比預覽。
Windows sandbox 曾在同一程序第二次建立 Tk 時拒讀 init.tcl；相關原生測試以獨立程序執行並單列結果。

開發版雙擊入口：`routinekeel/workflow_studio/open_studio.bat`。
Studio 是新增的設計工作台，沿用本機 Tk 模式並呼叫底座 WorkflowService；不是替換底座原有 UI。
