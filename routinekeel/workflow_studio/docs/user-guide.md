# 建立第一個工作流

工作臺採逐步操作：**工作目標 → 加入來源 → 確認流程 → 試做 → 發布**。
畫面每次只顯示目前步驟；「上一步／下一步」固定在下方左側。專案名稱直接可輸入，
不需要先按解鎖或定位按鈕。尚未符合條件的操作先隱藏，提示文字會說明缺少的資料。

這份練習使用本機成功案例，不需要模型或 API 金鑰。候選包的啟動方式見[安裝指南](distribution.md)。

## 先準備

- 在新的練習工作區操作。
- 找到包內的 [examples/first-copy](../examples/first-copy/input/a.txt)，其中有 input 與 output 資料夾。
- 準備新的空資料夾作為練習發布位置，例如「Studio 練習成果」。

## 1. 工作目標

直接填寫：

- 專案名稱：我的第一個複製流程。
- 要完成什麼工作：完整複製輸入文字檔。
- 怎樣算完成：輸出內容與正確成果完全相同。

按下方「建立專案並繼續」。只填名稱也能先保存草稿；目標與成功條件可用「上一步」回來補充。
整理來源時可以提出待確認問題，建立可執行流程與發布前仍須補齊必要條件。

已有專案時，按上方「開啟專案」，從清單選取，再按「開啟選取專案」。
專案清單不會佔據新專案表單。

## 2. 加入來源

按「資料夾」，選整個 examples/first-copy，包含 input 與 output。
來源會自動選取；在同一頁的唯讀預覽核對兩份檔案的內容。

按下方「從成功案例找流程」。這是本機比對，不會呼叫模型。
也可加入文字、檔案，或選擇手動建立流程；只有需要 AI 時才設定模型，送出前另有資料與預算確認。

## 3. 確認流程

選取候選並查看流程圖，按「採用選取的候選流程」保存版本與固定案例。
接著按「下一步：試做」。

採用後仍可調整步驟。需要詳細來源關係或證據管理時，使用「進階操作」。
若要重整既有流程，按「上一步」返回來源頁，選擇重新整理或重新比對；原版本仍保留。

## 4. 試做

本例的輸入與正確成果已由成功案例帶入。按「建立候選包並試做」，等待報告。
應看到「試做通過」，並核對實際成果與原成功條件相符。

失敗時保留報告與正確答案，依差異修改流程或補充資料。不要改預期成果來遷就錯誤輸出。
通過後按「下一步：核對與發布」。

## 5. 發布

填寫核准者姓名，勾選「已核對試做成果與工作目標」。
接著出現「確認並發布到本機工作區」，選擇先前準備的練習發布資料夾。

完成後可查看發布版本。這是安裝本機流程包，包含流程資料夾與 flow.json。
它不會自動發布到 GitHub 或對外寄送資料。

## 保存、重開與續編

關閉前保存輸入。重新開啟同一工作區，按「開啟專案」選取原專案，核對來源、流程與發布歷史。
修改後須對新版本重新試做與核准；「進階操作」提供版本差異、案例歷史與發布回復。

工作臺內的試做會透過獨立底座執行。正式執行時使用 RoutineKeel 底座的入口，
選取發布的流程，另給新的輸入與空輸出位置，保留原成果。

## 卡住時

| 情況 | 下一步 |
|---|---|
| 還沒有繼續按鈕 | 查看下方提示，先填專案名稱或目前必要欄位 |
| 沒找到資料夾候選 | 補齊 input／output，或使用該頁的手動建立／AI 整理 |
| 想修改前面的資料 | 按「上一步」；文字會保留，修改目標後先儲存 |
| 試做失敗 | 查看同頁報告，保留正確成果後修正流程 |
| 還沒有發布按鈕 | 先通過試做，再填核准者並確認成果 |
| 重開看不到專案 | 核對是否選擇同一個工作區 |
| 顯示外部更新衝突 | 按「比較更新」，核對後明確選擇要保存的內容 |

完整來源限制、費用、備份與回滾見[工作臺功能](workbench.md)、[來源格式](source-formats.md)、
[隱私與模型用量](privacy-and-model-usage.md)、[備份與回滾](upgrade-and-rollback.md)。
