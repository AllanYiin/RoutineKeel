# 建立第一個工作流

適用版本：Studio 0.1.0 開發候選。這份教學的目標，是讓已能開啟工作台的使用者，
用現成成功案例建立、試做、核准並保存一個複製流程。此例不需要模型或 API 金鑰。
候選包可依[安裝指南](distribution.md)準備；新視窗真人走查與最終交付仍待驗收。
使用原始碼環境時，啟動準備由管理者依[開發者指南](developer-guide.md)完成。

## 前置條件

- 已能開啟 Studio，並知道管理者指定的專案工作區位置。
- 準備隨原始碼提供的 [first-copy](../examples/first-copy/input/a.txt) 範例。
  匯入時選整個 `examples/first-copy` 資料夾，不要只選其中一個檔案。
- 準備一個新的空資料夾作為練習發布位置，例如「Studio 練習成果」。
  第一次走查先使用練習資料，不要選既有正式流程的安裝位置。

範例結構如下；input 與 output 內的文字相同，output 是已知正確成果：

```text
first-copy/
  input/a.txt
  output/a.txt
```

## 操作步驟

### 步驟 1（Step 1）：寫清楚目標

在「專案名稱」填入「我的第一個複製流程」；「要完成什麼工作」填入「完整複製輸入文字檔」；
「成功條件」填入「輸出內容與正確成果完全相同」。按「建立專案」。
預期結果（Expected result）：專案出現在清單，目標文字保留下來。

### 步驟 2：匯入並核對來源

使用左側的資料夾匯入功能，選取 `first-copy`。展開來源樹，點選 input 與 output 的檔案，
在「來源預覽」核對兩行實際文字。原始檔不會被改寫，Studio 保存一份本機版本。
預期結果：兩個檔案都可預覽，內容一致。若匯入遭拒，先看下方故障排除，不要改副檔名繞過檢查。

### 步驟 3：採用候選

選取這個資料夾來源，按「從成功案例找流程」，在候選清單選擇複製候選，再按
「採用選取的候選流程」。這個按鈕使用本機案例比對；本教學不使用「AI 整理選取來源」。
預期結果：中間出現流程步驟，「試做與發布」已有從案例建立的輸入與正確成果。
候選中的推論仍不是業務規則的人工確認；有疑問可先開「檢查案例關係與版本」。

### 步驟 4：試做並查看實際成果

在「試做與發布」按「建立候選包並試做」。等待結果，不要將「正在處理」當成通過。
開「建置歷史／審核／報告」查看該次報告；本例應通過，實際內容須與正確成果一致。
預期結果：看到通過狀態及可核對的成果。若失敗，保留報告，查看差異並回到來源或流程修訂。
不要為了通過而把正確成果改成錯誤輸出。

### 步驟 5：確認並發布到練習位置

核對成果與工作目標後，填寫「核准者姓名」，勾選「已核對試做成果與工作目標」，
按「確認並發布到本機工作區」，選取先前準備的練習資料夾。
預期結果：發布歷史出現一筆版本，目標位置產生流程資料夾及 `flow.json`。
這個操作只安裝本機流程包，不會發布到 GitHub，也不會自動對外寄送資料。

### 步驟 6：關閉、重開與續編

關閉工作台，再用相同的專案工作區開啟，選取剛才的專案。
預期結果：來源、流程、試做報告與發布歷史仍存在。
需要修改時使用「版本與差異」另存續編；新版本重新試做、核准，舊發布版本保持不變。
若要回復已發布的舊版，使用「發布歷史／回復舊版」，先核對目標工作區與版本。

## 驗證是否完成

這次練習完成的判斷是：來源可預覽、試做確實通過、發布歷史可查，而且重開後仍能還原專案。
已發布的流程由 RoutineKeel 底座執行；使用底座的操作入口選取該流程，另給新的輸入與空輸出位置。
輸入內容改變時請使用新的輸出位置，既有成果不會被其他工作直接覆寫。
本例的服務層重播會另外驗證發布包能獨立執行；這不取代你的視窗操作走查。

## 故障排除（Troubleshooting）

| 現象 | 處理方式 |
|---|---|
| 找不到候選 | 確認選的是含 input 與 output 的整個資料夾，兩份檔案都可預覽 |
| 「從成功案例找流程」不能按 | 先建立專案，並只選一個來源；多選不代表單一成功案例 |
| 試做指出缺少底座或環境不完整 | 請管理者核對 Runtime Python，保留該次本機 console.log |
| 發布不能按 | 確認當前版本已通過試做，姓名已填、成果確認已勾選 |
| 修改後舊核准不能使用 | 這是版本保護；先對新內容重新試做與核准 |
| 重開看不到專案 | 核對是否開啟同一個專案工作區，不要建立新資料庫取代原資料 |
