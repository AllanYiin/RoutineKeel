# 控制模型用量與資料傳送

## 目標與前置條件

適用 Studio 0.1.0。使用模型前先確認哪些內容會離開電腦、送到哪個端點、最多允許多少用量。
本機匯入、預覽、成功案例比對、確定性流程試做不需要模型金鑰。
費率由使用者依自己的 Provider 契約填入；程式沒有內建即時價格表。

## 操作流程

### 步驟 1（Step 1）：設定目的端與預算

在「模型與用量設定」填入 API 端點、模型名稱、金鑰、輸入／輸出費率與設計期預算。
不要把金鑰寫進來源文字、專案名稱、IR 或成果樣本。
非機密設定會隨專案保存；介面輸入的金鑰只保留在本次工作台程序使用的環境中，關閉後需重新提供。
它不是 OS 金鑰保險箱，也沒有在此宣稱程序記憶體加密。

```text
設計期：來源分析、生成修正、根據試做差異修復
執行期：工作流中明確宣告的模型節點
確定性步驟：不應因透過底座執行而額外呼叫模型
```

### 步驟 2：逐次核對送出範圍

| 操作 | 核對的內容 |
|---|---|
| AI 整理來源 | 選取來源、工作目標、已允許工具及目的端；單一資料夾會包含其全部來源檔案 |
| 靜態圖片分析 | 實際送出的全解析度 PNG；方向已校正、metadata 已移除，但圖中可見文字仍在 |
| 根據試做差異修復 | 目前 IR／生成程式、固定案例的完整輸入與預期、比較規則及差異；後續輪次含重測差異 |
| 含模型節點的試做 | 個別節點的端點、模型、案例資料與執行期預算；需獨立授權，不能沿用分析同意 |

送出準備綁定來源版本與 request hash。內容或目的端改變後，舊同意不適用。
模型回傳的文字不具有授權效力，不能自稱已獲寄送、檔案存取或發布權限。
來源副本不代表已完成匿名化；metadata 移除也不能移除圖片中可辨認的私人內容。

### 步驟 3：停止及核對紀錄

分析文字逐段出現，可按「停止分析」。停止會阻止後續工作，但不能撤回已送出的請求或費用；
已開始的隔離 Runtime 試做會先結束，介面不保證即時終止它。
串流斷線或不完整內容不會當成有效新版本。完成後查看設計期用量與該次 Runtime 報告，
不要把預留估算當成 Provider 最終帳單。

## 驗證預算與保存範圍

設計期與執行期分開記錄。請求前會預留上限，依實際 usage 結算；缺少完整 usage 時採保守記帳，
所以本機顯示可能不同於供應商帳單。預算不足會拒絕新呼叫，不會自動增加預算。
圖片預留預設 65,536 input tokens／張，是可調整估計，不是供應商計價保證。

本機 SQLite 保存匯入來源、版本、模型文字事件、案例與用量；生成程式與合成測試也可能包含輸入內容。
建置／驗證目錄保存套件、報告與 console.log。套件雖不自動附加所有原始來源，IR、程式、
證據說明與參數本身仍可能包含私人內容；分享前應檢查整包。
軟刪除、移除參照與封存會保留歷史，不是安全抹除。Studio 沒有宣稱磁碟資料加密或自動去識別化。
備份也應按相同敏感程度保存；不要把整個專案或診斷目錄當成可公開的測試素材。

## 故障排除（Troubleshooting）

- `PROVIDER_UNAVAILABLE`：確認目的端、模型與當次程序金鑰，不要將金鑰貼進錯誤報告。
- `BUDGET_EXCEEDED`：核對費率、預留量及既有用量；要增加預算時由你明確設定。
- `APPROVAL_REQUIRED`：重新核對本次資料與目的端，不能用另一模型的金鑰強行通過。
- 連線中斷：保留上一有效草稿，先查原因；外部結果不明時不要盲目重送。

Provider 端的保存、訓練使用與刪除政策由該服務決定，本專案無法代為保證。
目前真實付費模型用量與轉換品質仍未完成驗收，詳細限制見[已知問題](known-issues.md)。
