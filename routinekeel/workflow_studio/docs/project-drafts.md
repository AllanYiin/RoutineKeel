# 未儲存的目標與外部更新

主畫面的名稱、工作目標與成功條件是本機編輯草稿。背景分析、試做或來源整理完成後，
重新讀取同一專案時會保留尚未保存的文字與換行，不會用資料庫內容覆蓋它。
這不是自動儲存；關閉或切換時仍須選擇儲存、不儲存或取消。

只新增來源或建置而沒有改動這些欄位時，可以繼續儲存草稿。
若名稱、目標或專案狀態也被其他操作修改，畫面會顯示「外部更新待核對；草稿保留」，
並保留開始編輯時的版本。一般儲存不會自動取得新的版本號來覆蓋外部更新。

按「比較更新」查看開始編輯時、目前保存及未儲存內容，然後選擇：

- 保留草稿並關閉，不寫入資料。
- 明確捨棄草稿，重新載入保存內容。
- 以草稿更新畫面中已核對的版本。提交時再次檢查版本；比較後若又有變更，整筆拒絕並保留草稿。

封存或刪除狀態不允許更新。工作區或專案切換後，舊比較視窗不能把內容寫入其他專案。
同一專案重新選取不會丟掉草稿；未建立的新專案也有離開確認。取消切換或儲存失敗時，
保留原專案及輸入內容。介面未提供編輯的 goal metadata 會保留，不因修改可見欄位而被整份替換。

在準備模型資料時繼續修改目標，工作臺會停止該次送出，請先儲存後重新分析。
準備後專案版本若變動，也不使用舊請求。分析已經開始後輸入的新草稿不會更改已確認的請求，
完成後仍保留這份未儲存文字；後續操作須先處理草稿。

實作以 ProjectEdits 分開追蹤最新專案與編輯基準，仍使用既有 ProjectService 的 CAS 交易，
沒有 schema 遷移或新的資料儲存位置。回退前先儲存需要保留的草稿並備份現有工作區；
尚未儲存的文字只在目前視窗記憶體，不應把回退或重新啟動視為可還原草稿。
控制器與真實 SQLite 的測試已執行，新增比較視窗仍待原生桌面走查。
