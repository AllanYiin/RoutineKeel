# RoutineKeel 本機工作台

本機工作台提供檔案選擇、預先檢查、開始／取消、執行狀態、歷史成果與錯誤診斷。它使用 Python 標準函式庫的 Tk 及既有 `WorkflowService`，不開 Port、不要求雲端帳號，也不呼叫 LLM。

## 開啟

在發行工作區中雙擊 `flow_base/open_ui.bat`（Windows）或 `flow_base/open_ui.command`（macOS）；Linux 可執行 `flow_base/open_ui.sh`。這些入口沿用原有 `run_app` 安裝與啟動流程。若圖形環境不可用，原有 `run_app` 和 `flow_base` CLI 仍可使用。

開發環境可從儲存庫根目錄執行：

```powershell
uv run --locked --python 3.12 --project routinekeel/flow_base flow_base --workspace dist/workspace ui
```

## 完成一項工作

1. 按「開啟專案」選擇含 `flow_base` 與流程包的工作區。左欄列出已安裝工作流及歷史 Run。
2. 選擇工作流，再按「選檔」。預覽區顯示檔名、大小、格式；PNG／GIF 及 UTF-8 文字會顯示內容。其他格式或解碼失敗會明確標示「無法預覽內容」，仍可依流程契約執行。
3. 成果位置可留空使用流程預設值，也可用「選資料夾」明確指定。設定欄輸入 JSON object，例如 `{}`；可勾選離線模式。
4. 按「預先檢查」查看節點、成果位置與阻礙。排除阻礙後按「開始」。重複按開始會沿用相同 idempotency key；變更輸入或設定須重新檢查。
5. 工作台顯示持久化狀態及最後事件。按「取消」只代表已提出請求，必須等狀態轉為 `cancelled` 才算確定停止。成功後右欄列出已驗證的成果檔案與大小。
6. 關閉視窗後重新開啟相同專案，可從歷史 Run 查看既有狀態、成果與錯誤。搬移整個專案後用「開啟專案」重新選取新位置。

失敗時右欄顯示白話標題、失敗階段、原因確定程度、下一步及 `error_id`。需要維護者協助時按「匯出已遮罩診斷」，明確選擇新檔案並確認；不會自動上傳。若 Run 沒有已保存診斷，介面會說明無法匯出。

圖片縮放維持原始比例。此最小工作台沒有內建影片播放器、音訊波形、PDF 第一頁或 JPEG 解碼器；選到這些檔案時會顯示檔名、大小、格式與無法預覽的原因，不會顯示虛假的縮圖。流程本身的輸入支援仍由各流程包決定。

## 交付前操作走查

這份清單供未接觸原始碼的使用者，在**測試資料夾**中照步驟確認；請勿使用私人影片或憑證。

1. 建一個新的 `RoutineKeel-測試` 資料夾，將底座 ZIP 與「檔案複製範例」ZIP 解壓進去。確認 `flow_base/` 和 `檔案複製範例/` 並排。在資料夾內新建 `測試.txt`，寫入一行「這是測試」。
2. Windows 雙擊 `flow_base/open_ui.bat`；macOS 在 Finder 開啟 `flow_base/open_ui.command`。首次準備完成後應看到「RoutineKeel 本機工作台」，而非空白瀏覽器或網路登入頁。
3. 按「開啟專案」選 `RoutineKeel-測試`，選「檔案複製範例」與 `測試.txt`。畫面應顯示檔名、大小與文字內容；按「預先檢查」應看到成果位置且沒有阻礙。按「開始」後等待狀態為 `succeeded`，成果清單應有 `artifacts/result.bin`，內容與 `測試.txt` 相同。
4. 關閉工作台，重新開啟同一個專案；左欄歷史應仍有原 Run，點選後仍能看到成果。這一步確認狀態來自磁碟，而非原視窗記憶體。
5. 在輸入欄改填不存在的檔案，按「預先檢查」；畫面應說明問題、不能按「開始」。這是**尚未建立 Run** 的輸入錯誤，沒有 `error_id` 也合理。接著重新選取 `測試.txt`，再按「預先檢查」及「開始」，確認新 Run 變成 `succeeded` 且成果內容仍與原檔相同，完成錯誤後的復原。若另有已失敗的 Run，點選歷史項目應可見階段、確定程度、下一步與 `error_id`；選擇新檔名並確認後才會匯出已遮罩診斷。
6. 若要驗收 MCP 佇列，另開 `flow_base/queue_worker.*`，由已設定的 MCP Client 提交同一個測試檔案；記下 `execution_id`。關閉 Client 後重開，用該 ID 查狀態與成果。Worker 沒開時只應顯示 `queued`。

請記下操作系統、ZIP 版號、每步是否符合預期，以及任何看不懂的文字或無法開啟的視窗。macOS Finder、Tk 視窗與真人理解度不能由 headless CI 代替；未執行走查時應在發行檢核中保留「未驗證」。
