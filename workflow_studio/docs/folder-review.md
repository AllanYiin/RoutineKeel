# 成功案例的關係與角色

匯入成功案例資料夾，按「從成功案例找流程」，再開啟「檢查案例關係與版本」。
工作臺列出檔案角色、已比對的處理關係、待補證據、時間及日誌觀察。
可以選擇任一歷史證據圖版本，預覽當時保存的檔案；來源後來替換也不改寫舊預覽。

- 檔案角色可指定為輸入、成果、中間產物、日誌或未知。先設定選取檔案，再填決策者與理由，
  按「套用角色並重新比對」。待套用內容只保存在表單；可取消，切換／關閉前會提示未保存內容。
- 關係可以確認、排除，或替換成相同輸入與成果的另一個已比對處理方式。
  「改為待確認」取消此證據圖中的確認狀態。每次操作另存版本，保留操作者、理由與原關係。
- 修改角色會重新建立推論關係，先前確認不自動帶入。排除最後一條關係後，相關成果重新標記為待補證據。
- 來源已更新、證據圖已封存或正在查看舊版本時，只能查閱。重新分析目前來源後才能作出新決策。

「依目前關係產生候選」回到工作臺的候選清單，再選取並採用。
採用前會重新核對目前證據圖版本、來源、目標與工具；已排除的舊關係不能從記憶體候選重新套用。
具名且有理由的關係確認會轉成綁定來源版本、輸入／成果路徑、工具版本、參數與圖版本的人工確認紀錄，
與流程及 Golden Case 同交易保存。任一部分失敗時全部回復；舊圖未記錄理由的確認不自動升格。

樣本重現表示這個處理方式能產生這組樣本，不能證明歷史工作就是如此，也不代表所有新輸入都正確。
人工確認與機器 verified 分開，採用後仍須試做、驗收及發布核准。

已採用的流程是固定版本，後續修改證據圖不回寫它。要修訂已採用流程的規則或撤回相同規則的確認，
請使用「業務規則／證據確認」；已安裝流程也不會因調整案例關係而被自動卸載。

此版本沿用 v014 資料庫，在既有不可變證據圖 payload 新增可選決策歷史，沒有 schema 遷移。
回退前保存 Studio DB 與 projects 來源快照；不要以舊圖覆蓋新圖，已發布包保持原狀。
服務、持久化與真實底座試做已有測試；新視窗尚未實機走查。
