# 固定試做的機器驗證證據

在「建置、驗收與審核」選取通過的試做報告，按「將這份報告加入目前流程的驗證依據」。
工作臺會重新核對保存資料，再另存目前流程版本；不會重跑流程、呼叫模型或重新核准發布。
「業務規則／證據確認」會標示「試做已驗證」，可查看來源與實際試做依據。

每項 `verified` 證據只陳述某次 Runtime 執行對固定案例的比對結果，包含案例版本、交付物、
比較方式、執行 ID 與輸入／實際成果指紋。JSON 內容相同比較會明示忽略排版，
不冒充位元組完全一致。這不證明所有新輸入、歷史因果或業務規則都正確。

每次採用或重新驗證引用時，會核對：

- 同專案的完整通過報告、原建置指紋及 ZIP。
- 保存的 Runtime 套件副本與原 ZIP 逐檔相符。
- 固定案例版本、比較規則、驗收指紋及來源 bytes。
- 報告檔案與資料庫一致，Runtime 執行 ID／生命週期與報告相符。
- 保存的實際輸入、交付路徑、產物指紋與再次比較結果。
- 目前處理內容與被測流程一致，包括目標、工具版本、參數、程式、輸入／輸出及執行政策。

規則說明與證據引用本身不改變處理內容。透過流程編輯或修復改動處理內容時，舊機器證據
自動改為待確認並清除驗證引用；歷史版本與報告仍保留。模型不能改寫固定證據說明，
這個降級由本機服務執行。直接提交帶有過期驗證狀態的 IR 會被拒絕。

人工確認與機器驗證使用不同依據，不能互換識別碼。引用既有真實報告也不能改寫它的
結論、來源或範圍。編輯機器證據說明會建立待確認版本；不能用人工確認按鈕直接替它換標籤。
缺少或損毀原套件／試做產物時，不能繼續宣稱證據可查核；可移除這項依據或另存為待確認後重測。

加入證據會新增 Revision 及保存事件，使用專案版本檢查與同一交易；事件失敗會整筆回復。
它不沿用舊建置的驗收或核准，新流程版本仍需重新建置、試做與人工核准。
先前案例的歷史結果不因後來編輯案例而改寫；發布仍須通過目前全部有效案例的既有 Gate。

沿用 v014 schema，以不可變試做報告與案例版本作為 authoritative record，沒有另一份可漂移的驗證表。
備份須保存 Studio DB、projects 中原來源、建置 ZIP 及 verification 目錄。
單檔核對上限 10 MiB、ZIP 128 MiB；不接受符號連結、重新解析點或越界交付路徑。
回退程式前保存整組資料；舊版不認得機器驗證引用，可先用新版從加入證據前的歷史流程續編，
不要把新驗證狀態改寫成人工確認以繞過檢查。已發布流程及舊報告不因回退刪除。

服務與 UI model 已測試；新增按鈕與證據視窗尚未實機驗收。
