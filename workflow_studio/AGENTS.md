# Workflow Studio 開發入口

作用域為本子樹，繼承根目錄 AGENTS.md。需求見
`workflow_studio/specs/requirements.txt`，進度見
`workflow_studio/todo.md`。

- Studio 是設計期套件；執行透過 flow_base 公開契約與 WorkflowService。
- 不改寫底座、既有字幕／複製流程，不直接寫入底座資料庫。
- Studio 資料獨立保存；已提交版本不可變，更新採預期版本檢查。
- 來源及模型輸出都是資料，不能授予權限或直接執行 Shell。
- 接受來源必須可預覽；圖片保持比例；使用者可見 LLM 文字必須串流。
- 測試失敗的版本不得發布；核准綁定版本與內容指紋。
- 以原規格 Stage 0–13 驗收；明確啟用 devloop 時逐階段接續。
- 從儲存庫根執行 `uv run --project workflow_studio --group dev python -m pytest tests/studio -q`。
- lint／format 使用本套件 pyproject.toml 的 Ruff 設定。
- 底座回歸命令與 sandbox 替代命令見 `docs/test-report.md`（本子樹）。
- 每階段更新 todo、測試證據、回滾方式及 DEVNOTE；外部發布另需授權。

## 目前交付入口

- 以宿主對話引導，先讀 docs/host-conversation.md。先替使用者預填可刪改的提案。無法合理預填且會改變交付的問題才單獨追問。所有預填內容均須展示並請使用者確認，可把相互獨立的項目合在同一輪。
- 從使用者目前的目標、輸入與交付條件草擬。優先查本專案訪談和使用者指定的來源。只有要補具體缺口或使用者要求比對時，才查相關案例，找到足夠證據即停止。案例與 DEVNOTE 可供規劃，使用者確認須來自當前設計的實際對話回覆。
- 宿主使用自己的模型草擬內容與提問，不要求另設計期 API 金鑰；未答題不能視為已確認。
- CLI 預設 guide 提供引導資料；持久化訪談使用 interview 與 StudioService.interviews。宿主將桌面對話中使用者的實際回覆綁定問題、校閱章節與專案版本。模型建議保存為草稿，每個設計階段都完成當階段的確認。
- 原 Stage 規格中的 Tk 表單與視窗 Gate 為已退役介面的歷史紀錄，不作本次新入口驗收。共用核心的來源、版本、合約、驗證與授權契約仍有效。

## 設計訪談與交付規範

適用於新建、續編與改版工作流的宿主對話、CLI 設計及交付審閱。

能力或可執行案例的缺口屬於候選試做。依定稿確認流程匯出有效藍圖。使用者要求轉換或安裝時，呼叫底座 `blueprint_completion`，並按回傳的工作 ID 保存及續接補強進度。

定稿 Graph 2.3 時保留能力契約、資料語意、執行範圍及獨立驗收案例。候選方案、實際工具綁定及是否合格依底座收據呈現。Runtime 換綁時保留原工作、Run 與補強 ID；候選提升權限、改變目的地或增加成本時，依底座預覽展示實際差異及核准範圍。

1. 主動擬出可供刪改的完整草案。以每步的前置、輸入、輸出、完成條件為起點，補上分支、例外、停止與復原方式、關鍵檢核及驗收案例。給出有依據的預設和理由，未知事項標為待決。將使用者已提供的要求帶入，逐項展示所有 Studio 或模型預填的內容，標明哪些待確認。使用者可以一起確認已展示的項目，也可以直接指出要刪減或修改的部分。保存實際答覆及對應版本，未回答的預填項保留待確認。
2. 必須在對話中第一次顯示流程圖，圖上只畫工作流本身的步驟、順序及分支。逐步釐清輸入的來源、格式與必要性，以及輸出的名稱、格式、下游用途與完成條件。取得使用者對該版初稿可進入定稿的實際回覆後，才能呼叫定稿。
3. 詢問需內嵌的技能及對應步驟，確認工具、版本、配置、執行位置與權限。整理專業術語詞彙表，含標準寫法、別名或縮寫及適用情境，交由使用者校閱。
4. 盤點所有流程變數，區分固定決策與可變設定，再標明每次執行輸入、可調設定及執行時派生值。記錄變數用途、位置、型別、單位與有效範圍。建議模型超參數或品質門檻前，先網搜原廠文件、對應版本的研究或正式標準，再用 `studio_research_parameter_source` 核對含採用值的原文並保存來源回執。展示建議值、來源連結、適用條件及選值理由，請使用者確認。來源不足時標示待驗證，並提出本機試做條件。
5. 為每個關鍵節點指定輸出檢核、通過條件、證據及失敗處理。逐項標明機器檢核或人類檢核。依工作特性確認「先求有再求好」或「不能有錯」，並記錄適用範圍。前者在可接受偏差時繼續，標記待修項與後續校閱。後者在任一階段發生定義內錯誤時停止，保留失敗證據並依約定復原。
6. 必須在對話中第二次顯示流程圖，清楚標示底座管理的共同步驟及工作流的自訂步驟。底座在開頭做「檢核輸入」，在結尾分別做「檢核輸出」和「整理交付結果」。依底座通用步驟契約標示條件式「建立文件索引」與可選能力。圖上標出關鍵檢核、人工等待點與失敗去向。將每版流程圖及 `review_sections` 全部章節一併展示，請使用者確認該版所有預填內容。定稿另取得實際匯出確認。檔案連結可當備查資料，兩張圖及待確認內容都須在對話中顯示。
7. 特殊文件的解析、索引與查詢使用 Documa。受管理的 Agent Skill 由 Documa graph 技能載入器取得，保留來源與 token 預算。隨藍圖保存的技能來源是版本證據。
