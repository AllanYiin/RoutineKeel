# 在桌面對話使用 RoutineKeel

第一次由安裝者把完整候選包解壓到新的工作區，準備底座、Studio 與本機 MCP 連線。日常使用只需在同一個桌面對話提出要求。你的回覆會連同問題與工作版本保存。[宿主連線設定](mcp-local.md)

## 建立工作流

告訴宿主你重複做什麼、希望交付什麼。例如「把品名整理成原文和大寫兩欄，交付前給我看一次」。Studio 會詢問還缺的條件。你可以指明哪些步驟需要你決定，其餘步驟可以自動檢查資料後繼續。暫停後可從原專案編號續編。

確認設計摘要前，先看具名交付、重要規則及至少一個預期例子。以這個例子來說，輸入「Gear」應得到原文「Gear」和大寫「GEAR」。若希望只在交付前校閱，摘要中應只有這一個校閱點。

確認後，Studio 匯出藍圖。底座建置另一份候選工作流套件，先在臨時工作區載入它並實際跑驗收案例。通過後才能把同一份套件安裝到正式工作區。若有工具缺口或輸出不符，對話會指出原因，草稿可修改後再測。[藍圖建置與安裝](blueprint-install.md)

## 執行工作流

說「用剛才的流程處理這筆資料」。宿主先顯示輸入、預覽狀態、需要的工具和交付項目。圖片或影片維持比例，若無法解碼會說明原因。提交後可憑執行編號查進度。

| 對話狀態 | 可以怎麼做 |
| --- | --- |
| 已排隊 | 保留執行編號。工作區的 Worker 啟動後會領取工作。 |
| 正在執行 | 可查已完成節點或要求取消。等到狀態變成已取消才代表停止。 |
| 等待回覆 | 閱讀指定節點的問題與成果，在原對話回覆。對外操作會顯示具體動作及其範圍。 |
| 已處理完成 | 查看具名成果與品質判定。尚待驗收的預覽可以修正，通過的版本才成為正式交付。 |

關閉並重新開啟宿主後，說「接續這次工作」並提供先前的執行或工作編號。宿主會讀回已保存的節點與成果，從需要你回覆的地方繼續。[品質驗收與回饋](graph-quality.md)

## 改善工作流

說明是哪次工作的哪個結果需要修正。只調整這次交付，可以針對有問題的部分修正與重驗。想改變以後每次的處理方式，則建立修訂提案。候選版要經固定案例、這次暴露的缺陷案例與獨立驗收案例比較。你在桌面對話看過結果並確認後才切換正式版。更新收據可用來退回前版。[版本比較與回退](workflow-evolution.md)

## 最後的真人走查

請第一次使用的非技術使用者在已連接的測試工作區，直接用自己的話操作。

1. 請宿主建立上述文字整理流程，指明只在交付前校閱。中途關閉並重開對話，接續原訪談。
2. 檢視設計與「Gear」的預期結果。請宿主測試候選套件，通過後安裝。確認正式流程清單能找到它。
3. 以新的文字執行。在指定校閱點回覆，再打開具名成果。對照原文、大寫與品質狀態。
4. 指出一項想改進之處，檢視修訂前後差異。決定採用或保留原版。若選擇採用，實際退回前版後再執行一次。

記下哪一題難以理解、曾在哪一步需要離開對話，以及交付是否符合預期。真人體驗結果由操作的人填寫。[支援範圍](known-issues.md)
